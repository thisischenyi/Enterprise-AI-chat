## v1 Requirements — Final Status

### Authentication

- [x] **AUTH-01**: Employee can sign in through OIDC authentication (mock OIDC for MVP) — ✅ Validated in Phase 1
- [x] **AUTH-02**: Backend routes have access to authenticated user identity (user ID, role) — ✅ Validated in Phase 1
- [x] **AUTH-03**: Role distinction between employee (chat access) and admin (config + audit access) — ✅ Validated in Phase 1

### Chat

- [x] **CHAT-01**: Employee can select an allowed model provider — ✅ Validated in Phase 2 (DB-first ProviderRegistry)
- [x] **CHAT-02**: Employee can send a chat message and receive a response through the backend — ✅ Validated in Phase 2
- [x] **CHAT-03**: Chat responses stream with safety buffer — ✅ Validated in Phase 4 (SentenceBuffer + SSE)

### Safety Pipeline

- [x] **SAFE-01**: Input safety filtering runs before every model call — ✅ Validated in Phase 2
- [x] **SAFE-02**: Output safety filtering runs before every response display — ✅ Validated in Phase 2 + Phase 4
- [x] **SAFE-03**: Policy violations block the full input or output, no partial redaction — ✅ Validated in Phase 2
- [x] **SAFE-04**: Block messages explain risk category without echoing content — ✅ Validated in Phase 2 (Chinese templates)
- [x] **SAFE-05**: Audit event metadata recorded for every allow and block decision — ✅ Validated in Phase 2
- [x] **SAFE-06**: Audit events contain metadata only, never raw content — ✅ Validated in Phase 2
- [x] **SAFE-07**: Scanner failures default to BLOCK (fail-closed) — ✅ Validated in Phase 2 (30s timeout)
- [x] **SAFE-08**: Custom Presidio recognizers for enterprise PII — ✅ Validated in Phase 2 (ChineseNationalId, EmployeeId, ProjectCode, Income)

### Conversation History

- [x] **HIST-01**: Employee can browse past conversations — ✅ Validated in Phase 3
- [x] **HIST-02**: Employee can resume a past conversation and continue chatting — ✅ Validated in Phase 3
- [x] **HIST-03**: Database stores only allowed-through content — ✅ Validated in Phase 3
- [x] **HIST-04**: Blocked messages generate audit entries, no Message rows with raw content — ✅ Validated in Phase 3

### Admin Dashboard

- [x] **ADMN-02**: Admin can configure model providers and credentials through dashboard — ✅ Validated in Phase 4 (Fernet-encrypted keys)
- [x] **ADMN-03**: Admin can configure policy thresholds and scanner modules — ✅ Validated in Phase 4

### Testing

- [x] **TEST-02**: Automated tests for input block path — ✅ Validated in Phase 2
- [x] **TEST-03**: Automated tests for output block path — ✅ Validated in Phase 2

## Requirements Outcomes

**All 25 v1 requirements validated.** No requirements were dropped or significantly adjusted during development.

Key adjustments:
- LLMGuardrailScanner renamed to ContentGuardScanner — same interface, different underlying model (Qwen3Guard vs LLM Guard toxicity)
- Streaming uses SentenceBuffer (full-response-first) instead of per-chunk streaming from LLM — safety semantics unchanged
- SQLite WAL mode for MVP instead of PostgreSQL from day 1 — same ORM, easy migration path
