# Milestone v1.0: MVP

**Status:** ✅ SHIPPED 2026-05-23
**Phases:** 1-4
**Total Plans:** 13

## Overview

Enterprise AI chat web application that lets authenticated employees chat with approved LLMs while enforcing input and output safety controls. The MVP proves that AI chat can be used safely in an enterprise environment — blocking sensitive content before model calls and blocking unsafe model responses before display.

## Phases

### Phase 1: Foundation & Auth

**Goal**: Employees can securely authenticate and the backend knows their identity and role
**Depends on**: Nothing (first phase)
**Plans**: 3 plans

Plans:

- [x] 01-01: Backend Walking Skeleton — project scaffold, DB schema, mock OIDC auth routes, auth middleware
- [x] 01-02: Frontend Auth UI — mock OIDC login flow, role selector, Zustand auth store, authenticated home page
- [x] 01-03: Role-Based Access Enforcement — admin-only endpoint guards, role tests, frontend route guards

**Details:**
- SQLAlchemy async ORM with SQLite (aiosqlite) for MVP, PostgreSQL for production
- Mock OIDC with session-based auth (itsdangerous TimedSerializer)
- FastAPI dependency injection: get_current_user, get_db_session
- Zustand auth store with session persistence (localStorage)
- AuthRestorer component for session restoration on mount

### Phase 2: Safety Pipeline & Chat

**Goal**: The safety pipeline reliably blocks unsafe content and employees can chat through it
**Depends on**: Phase 1
**Plans**: 5 plans

Plans:

- [x] 02-01: Scanner Interfaces + DataProtectionScanner + ContentGuardScanner + Custom Recognizers + Block Messages
- [x] 02-02: SafetyPipeline + SafetyPolicy + AuditEvent + AuditRepository
- [x] 02-03: Model Providers + Chat API + Frontend Chat Page
- [x] 02-04: Integration Tests + Test Fixtures + Chat API Tests
- [x] 02-05: Replace toxicity model with Qwen3Guard-Gen-0.6B generative model

**Details:**
- Scanner Protocol with ScannerResult, ScannerFinding, PolicyDecision, RiskCategory types
- DataProtectionScanner: Presidio with regex-only entities (score threshold 0.7), NLP-dependent recognizers removed to prevent Chinese false positives
- ContentGuardScanner: Qwen3Guard-Gen-0.6B generative model + 22 injection regex rules + 11 harmful content regex rules (bilingual Chinese + English)
- SafetyPipeline: asyncio.gather parallel scan with 30s timeout, fail-closed semantics
- Block messages: Chinese category-specific templates that never echo content
- ProviderRegistry: DB-first model config with Fernet-encrypted API keys
- AuditEvent: metadata-only, never stores raw prompts or model outputs

### Phase 3: Conversation History & Chat Interface

**Goal**: Employees can browse and resume past conversations through a chat interface, with only allowed-through content stored
**Depends on**: Phase 2
**Plans**: 2 plans

Plans:

- [x] 03-01: Backend conversation persistence — Conversation/Message DB models, ConversationRepository, API endpoints, storage boundary (only allowed-through content)
- [x] 03-02: Frontend conversation sidebar + resume + new conversation flow

**Details:**
- ConversationRepository: list_for_user, get_conversation (owner-scoped), add_message, delete_conversation
- Blocked messages stored with "blocked" role containing block template (not raw violations)
- ConversationSidebar: date-grouped list, click to resume, auto-select model
- Delete conversation with confirmation dialog (Chinese text)

### Phase 4: Streaming & Admin Dashboard

**Goal**: Chat responses stream with safety buffering, and admins can view audit data and manage configuration through a dashboard
**Depends on**: Phase 3
**Plans**: 3 plans

Plans:

- [x] 04-01: Streaming chat with SentenceBuffer safety scanning and SSE events
- [x] 04-02: Admin audit viewer with stats, filters, and paginated table
- [x] 04-03: Admin model provider and policy scanner configuration (Fernet-encrypted API keys, CRUD, toggle, delete)

**Details:**
- StreamingChatService: input scan → model call → SentenceBuffer sentence splitting → output scan per sentence → SSE events (chunk/block/done/error)
- SentenceBuffer: regex sentence boundary splitting, full-response-first approach (not per-chunk streaming from LLM)
- Admin audit viewer: paginated table with risk category and action filters
- Admin model config: ModelConfig CRUD with Fernet encrypt/decrypt/mask, seed from env vars, DB-first ProviderRegistry
- Admin policy config: PolicyConfig toggle enable/disable per scanner, sensitivity settings

## Milestone Summary

**Key Decisions:**

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Mock OIDC first | Enterprise IDP not yet determined; mock lets MVP focus on core chat + safety pipeline | ✓ Good — real IDP adapter ready for swap |
| Qwen3Guard-Gen-0.6B over LLM Guard toxicity | LLM Guard's toxicity model completely ineffective for Chinese text (0.2-0.4 scores on everything); Qwen3Guard is a generative model with Chinese support | ✓ Good — effective bilingual detection |
| DB-first ProviderRegistry over env-var-only | Admin changes should take effect without restart; env vars only seed initial configs | ✓ Good — admin config changes propagate immediately |
| SQLite WAL for MVP | Proven for 100-user scale, easy migration to PostgreSQL later via SQLAlchemy abstraction | ✓ Good — MVP works, production path clear |
| Presidio regex-only entities | NLP-dependent recognizers (PERSON, LOCATION) cause massive false positives on Chinese text; regex matches (email, phone, SSN) are reliable | ✓ Good — zero Chinese false positives |
| SentenceBuffer (full-response-first) | Gets full model response, splits on sentence boundaries, scans each sentence; simpler than per-chunk streaming while still providing sentence-by-sentence display | ✓ Good — simpler implementation, reliable safety |
| Chinese block message templates | Block messages must never echo detected content; category-specific Chinese templates satisfy enterprise requirements | ✓ Good — bilingual, no content echoing |

**Issues Resolved:**

- Fixed toxicity model bug: llm_guard's Toxicity scanner internally filters by `_toxic_labels=["toxicity"]`, but model label is `toxic` (singular) — all detections silently dropped
- Fixed UnicodeEncodeError: Python on Windows with cp1252 codec can't encode Chinese characters — set PYTHONIOENCODING=utf-8
- Fixed 204 No Content JSON parse error: apiClient tried response.json() on empty 204 response, throwing SyntaxError — added explicit 204 handling
- Fixed model selection resetting after conversation: over-triggering useEffect on conversations data refresh — moved auto-select to onClick handler only
- Fixed duplicate model seeding on restart: added idempotent check (only seed when no ModelConfig records exist)
