<objective>
**As a** safety pipeline developer, **I want to** build the pipeline coordination, policy evaluation, and audit recording, **so that** unsafe content is reliably blocked, scanner failures fail-closed, and every decision has an audit trail with metadata only.

Purpose: The pipeline ties the scanners together into a coherent safety decision flow. Without the pipeline, scanners detect violations but can't coordinate blocking decisions. Without audit, there's no compliance trail. This plan makes the safety pipeline operational.

Output: Working SafetyPipeline that coordinates scanners with 30-second timeout, SafetyPolicy that aggregates findings into allow/block/fail-closed decisions, AuditEvent table with metadata-only storage, and AuditRepository that records every decision.

</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Scanner results → Policy | Scanner findings must be aggregated without echoing raw values into policy decisions |
| Policy → Audit | Policy decisions stored in audit_events with anonymized metadata only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05 | Information Disclosure | Audit event storage | mitigate | scanner_findings contains anonymized type labels only (e.g. "Detected SSN") — never raw values per SAFE-06 |
| T-02-06 | Denial of Service | Pipeline timeout | mitigate | 30-second timeout on full pipeline prevents hanging requests; fail-closed returns block decision per D-SF01 |
| T-02-07 | Tampering | Policy evaluation | mitigate | Any violation → full block; no partial display bypass per SAFE-03 |
| T-02-08 | Information Disclosure | Block messages in audit | mitigate | Block message stored in audit is the category template, not the user-facing rendering — no raw content echo |
</threat_model>
