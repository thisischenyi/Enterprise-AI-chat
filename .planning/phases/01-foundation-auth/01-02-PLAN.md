<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> Backend API | Frontend sends role selection and mock tokens to backend; backend validates these before creating sessions |
| Backend -> Browser | Backend sets session cookie; frontend trusts cookie presence but backend must validate on each request |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Spoofing | Role selector | mitigate | Backend validates role parameter against allowed values ('employee', 'admin'); frontend cannot forge roles beyond these two mock values |
| T-01-06 | Tampering | Mock state token | mitigate | Frontend passes mock_state_token from login to callback without modification; backend validates signature with itsdangerous before accepting |
| T-01-07 | Information Disclosure | Session cookie | mitigate | Cookie set with HttpOnly flag by backend; frontend JS cannot read raw cookie value; only /api/auth/me endpoint returns user identity |
| T-01-08 | Elevation | Frontend route guards | accept | Frontend route guards are UX convenience only; real enforcement happens in backend middleware (get_admin_user). Frontend bypass does not grant actual admin access |
</threat_model>
