<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Frontend route guard -> Backend API | Frontend guards are UX convenience; backend middleware is the real enforcement. Bypassing frontend guard does NOT grant admin API access |
| Employee user -> Admin endpoint | Employee role cannot access admin endpoint; 403 response does not echo user identity or sensitive data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-09 | Elevation | Frontend route bypass | accept | Frontend bypass only skips UX guard; backend get_admin_user middleware returns 403 regardless of frontend navigation |
| T-01-10 | Information Disclosure | 403 error response | mitigate | 403 response body contains generic "Admin access required" message only; no user identity, no endpoint details, no role enumeration hints |
| T-01-11 | Elevation | Role parameter injection | mitigate | Backend validates role against CHECK constraint in DB ('employee', 'admin'); frontend cannot inject arbitrary roles beyond these two values |
</threat_model>
